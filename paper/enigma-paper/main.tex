\begin{abstract}
We consider agentic triage systems which come with hand designed epistemic
controls, for example a hypothesis that cannot be pruned, a gate that adds
doubt when the evidence is thin, a decay rule that penalises contradicting
evidence more than it rewards supporting evidence, and a requirement that a
belief persists for some time before the system acts on it. Mechanisms of this
kind are short pieces of code and they are easy to describe in a system paper,
but they are seldom checked. We audit four such mechanisms in a working
intrusion triage system, in which a LangGraph reasoning loop reads the output
of a deep ensemble sensor trained on UNSW-NB15. The audit is a $2^4$ factorial
over the four mechanisms, with three convergence thresholds and five seeds,
which gives 9600 reasoning units run against a real language model. We find
that one mechanism works, a second one works but largely repeats the first, a
third has no effect that five seeds can resolve, and the fourth, which is
described as a persistence requirement, is in fact a clamp on the convergence
score. The sixteen configurations give only five distinct outcomes. We also
show that the sensor level of the two level abstention design is never read by
the reasoning loop: clearing the abstention flag on every signal of the suite
changes the outcome by $0.000000$. To test the persistence diagnosis we repair
it. When a restated hypothesis keeps the identity of its predecessor, the
recurrence of hypotheses goes up from $0$ to $0.2045$ and the persistence
requirement starts to gate convergence, with no additional model calls. A null
result in an ablation can mean that a mechanism does little, or that it is not
connected at all, and so we suggest that the connection is checked before the
effect is measured.
\end{abstract}

\section{Introduction}

\textbf{Background.}
An agent which triages security alerts has to decide what is happening, and it
also has to decide whether it has enough evidence to say so. A common way to
deal with the second question is to add explicit mechanisms for doubt. For
example, a hypothesis standing for `unknown' may be kept permanently in the
hypothesis set, so that the named explanations always have something to
compete with. A gate may look at the hypothesis set and add doubt when there
is little evidence. Confidence may be allowed to decrease faster than it
increases. Finally, the system may be required to see the same hypothesis lead
for a few consecutive iterations before it acts on it. Each such mechanism
takes a few dozen lines of code, and in a system description each of them is
usually listed as a contribution.

\textbf{The audit question.}
It is easy to add a mechanism like this, and much harder to check that it is
connected to anything. In practice the check is rarely made. The evidence
usually given is an ablation: the mechanism is removed, the headline metric
changes, and the mechanism is said to matter. The difficulty comes when the
metric does not change. There are then two explanations which give the same
entry in the results table. Either the mechanism does a small amount of real
work, or no execution path reaches it and it does nothing at all. The ablation
on its own cannot tell these two cases apart, and the second case is the more
worrying one. Thus the usual evidence says least in the case where it is most
needed.

\textbf{The system and the results.}
We audit four mechanisms of this kind in a working system. The sensor is a deep
ensemble trained on UNSW-NB15~\cite{moustafa2015}, with temperature scaling and
a reject option. The reasoning layer is a LangGraph loop driven by
\texttt{gemini-2.5-flash}, and it runs over a frozen suite of 40 scenarios with
66 situations and 963 signals. Between the sensor and the loop there is an
information barrier, which passes ten aggregate fields to the loop and no raw
signal. The four mechanisms are the non-prunable \textsc{unknown} hypothesis
($U$), the sanity gate ($S$), asymmetric confidence decay ($A$) and the
persistence requirement ($P$).

Most of what we find is negative, and we regard the negative results as the
main contribution of the paper. Two of the four mechanisms have no effect that
five seeds can resolve. The sixteen configurations of the factorial give only
five distinct outcomes, and these five are determined by $U$ and $S$ alone.
Almost all of the effect comes from one evidence regime. In the code, the
persistence requirement is a clamp which keeps the convergence score just below
the configured threshold. It is never satisfied, because the generation step
builds a new hypothesis list at every iteration, and so no named hypothesis
lasts long enough to persist. In 963 analyses with more than one iteration
there are 10{,}068 named hypotheses, and none of them appears in two
iterations.

The system is also described as abstaining at two levels, first at the sensor
and then in the reasoning loop. We find that the sensor level is not enacted.
The abstention flag is counted into the reasoning snapshot but no decision
reads it, and clearing it on every signal of the suite changes the outcome by
$0.000000$.

\textbf{The repair.}
The persistence diagnosis comes from reading the code and from a null effect,
so it is only correlational, and one may ask whether the mechanism would work
if its precondition held. To answer this we supply the precondition. A newly
generated hypothesis takes the identifier of the earlier hypothesis it
restates, and nothing else is changed. The descriptions and the confidences are
those produced by the model, the prompts are the same as before, and the
experiment needs no new model calls. With the repair, recurrence goes up from
zero to $0.2045$, the dominant iteration counter reaches three (before the
repair it never went above one), and the persistence requirement gates
convergence for the first time. So the mechanism itself was specified
correctly, and the defect is in the way it is connected to the generation
step.

\textbf{Contributions.} The paper has four contributions. (i)~An audit method
for epistemic controls which distinguishes a mechanism that is \emph{inert}
from one that is \emph{disconnected}, together with verdicts on five mechanisms
of one real system (Section~\ref{sec:findings}). (ii)~A $2^4$ factorial at 9600
units, which tests a diagnosis made before the factorial was run
(Section~\ref{sec:confirmation}). (iii)~A repair experiment which leaves the
prompts unchanged and shows that the coupling defect is the cause
(Section~\ref{sec:repair}). (iv)~An evaluation hazard, in which a timing defect
raises the headline metric by $0.28$ and at the same time makes the system
worse at the only task where it has to commit (Section~\ref{sec:hazards}).

All numbers in the paper are recomputed from committed machine readable results
by a script which needs no API key and no network connection. On a clean
checkout all eighteen of the quoted numbers are reproduced.

\section{Related Work}

\textbf{Machine learning in security.}
Chandola et al.~\cite{chandola2009} survey anomaly detection. Sommer and
Paxson~\cite{sommer2010} explain why anomaly detection is harder to evaluate
than much of the earlier literature assumed. Arp et al.~\cite{arp2022} list
ten common pitfalls of machine learning in security, and they find at least
three of them in each of the thirty papers they examine, the most frequent
being sampling bias and inappropriate baselines. Pendlebury et
al.~\cite{pendlebury2019} show that when temporal ordering is ignored, malware
classification results are inflated so much that they say very little. These
papers check whether a reported number can be trusted. Here we check something
slightly different, namely whether a mechanism described in a paper is present
in the system that actually runs.

\textbf{Technical debt.}
Sculley et al.~\cite{sculley2015} describe the hidden costs which build up in
machine learning systems, among them boundary erosion, undeclared consumers and
configuration debt. The defect we report is close to their undeclared consumer
but in reverse. A field is computed, passed through the system and documented,
and then nobody reads it. Amodei et al.~\cite{amodei2016} discuss problems of
this general type under the heading of scalable oversight. Neither work gives a
procedure for measuring such defects, and this is what we try to supply.

\textbf{Testing and the oracle problem.}
When it is not clear what the correct output of a program should be, we have
the oracle problem, which is surveyed by Barr et al.~\cite{barr2015}. The
problem is particularly hard for machine learning systems, see the survey of
Zhang et al.~\cite{zhang2022}. Metamorphic testing~\cite{chen2018metamorphic}
avoids it by checking relations between several executions, instead of
checking individual outputs. Our ablation can be seen as a metamorphic relation
of a particular kind. If a mechanism is connected, then disabling it must change
the output. Hence when two configurations agree to four decimal places, we
treat this as a violated relation, and we do not read it as a small effect.

\textbf{Selective prediction and abstention.}
The reject option goes back to Chow~\cite{chow1970}. Later work includes the
maximum softmax baseline of Hendrycks and Gimpel~\cite{hendrycks2017}, the
integrated reject option of Geifman and El-Yaniv~\cite{geifman2019} and the
calibration study of Guo et al.~\cite{guo2017}. Our sensor is a deep ensemble
as in Lakshminarayanan et al.~\cite{lakshminarayanan2017}, with temperature
scaling. All of this work is about a single classifier which may decline to
answer. The system we audit claims to abstain at two levels, and one of our
findings is that the two levels are not connected.

\textbf{Evaluation of guardrails.}
The work of Das Antar et al.~\cite{dasantar2025} is the closest to ours. They
measure the contribution of individual moderation guardrails, and of their
interactions, with a Bayesian procedure. They also point out that most
evaluations compare a system with and without the whole guardrail stack, which
says little about any one component. Kumar et al.~\cite{nofreelunch2025} report
that guardrails have a measurable cost in utility. Recent work on agent safety
also reports ablations in which each component turns out to be critical.

As far as we know, the following distinction has not been made before. The
work above measures how much a guardrail contributes, and it assumes that the
guardrail is on the execution path. This assumption is not tested. In the
system we report it fails for two of the five audited mechanisms, and an
ordinary ablation would have recorded both failures as small effects.

\textbf{LLM agents for triage.}
There is active work on multi-agent architectures for alert triage. For
example, CORTEX~\cite{cortex2025} combines agents for behaviour analysis,
evidence gathering and reasoning, and it reports fewer false positives than
single-agent baselines. Systems of this kind are natural candidates for the
audit we describe. We do not claim that the system audited here is the best of
its kind. We use it as an instrument, and we see no reason why a stronger
system would be less likely to have defects of the type we report.

\section{The System Under Audit}

The system has three layers. A sensor reads UNSW-NB15 flows and emits signals,
each of which carries an anomaly score, a predicted class and an abstention
flag. The sensor is a deep ensemble with temperature scaling and a reject
option, and it abstains on $22.85$\,\% of the signals in the evaluation suite.
A situation store groups the signals by entity into situations. A LangGraph
reasoning loop then runs at most three iterations on each situation. In each
iteration it generates hypotheses with \texttt{gemini-2.5-flash} at temperature
$0.2$, evaluates them against the evidence, and stops if a convergence score
passes a threshold, which is $0.8$ by default.

The store and the loop are separated by an information barrier. The context
assembly step passes ten aggregate fields to the loop, for example the evidence
count, the event rate, the burst and quiet indicators, the trend label, the
source diversity and the mean anomaly score. The model does not see raw
signals, entity identifiers, timestamps or signal identifiers. This is a
deliberate design choice, and it has a cost which we measure in
Section~\ref{sec:threats}.

The four audited mechanisms are inside the loop. Each of them can be removed
from the compiled graph, so an ablation does not depend on a flag being
respected. Figure~\ref{fig:arch} shows where each mechanism acts. It also shows
two things which a usual block diagram would leave out: three adapters which
are written and tested but never routed to, and the abstention path which the
system specifies but does not enact.

\section{Audit Method}
\label{sec:method}

\textbf{The test suite.}
The evaluation suite was generated once and hashed, and it has not been
regenerated since. The full suite has 400 scenarios. The sub-suite used for
the factorial has 40 scenarios, 66 situations and 963 signals, and its content
hash begins with \texttt{a2b37f29}. Every scenario belongs to one of four
evidence regimes, and the regime determines the correct behaviour. In the
\emph{clear} regime the system should conclude, and in the \emph{ambiguous},
\emph{sparse} and \emph{unknown attack} regimes it should abstain. Since the
correct behaviour is fixed when the scenario is generated, the abstention
metrics do not suffer from the oracle problem. The conclusion metrics still
do, see Section~\ref{sec:threats}.

\textbf{Metrics.}
The set of metrics was written down in the project evidence file before the
factorial was run, and we report it in that form. Four metrics are
\emph{live}: the abstention rate, the appropriate abstention rate, the
inappropriate abstention rate and the premature convergence rate. Each of them
depends only on whether the system concluded or abstained, and on the evidence
count when it stopped. In particular none of them uses keywords, and none of
them depends on which narrative the scenario is about. Two further metrics are
reported with a caveat. Two more were marked as \emph{dead} in advance, because
they do not move at the standing threshold. The threshold sweep in
Section~\ref{sec:findings} checks whether a lower threshold brings them back.

\textbf{Ablation by removal.}
A mechanism is ablated by removing its node from the compiled graph, and not by
setting a coefficient to zero. This is important when the results are
interpreted, since a cell in which a mechanism is ablated has no trace of that
mechanism left in it.

\textbf{Caching of responses.}
Model responses are cached under a hash of the fully assembled prompt. This
makes a grid of 9600 units affordable, and it also makes the grid repeatable.
The cache hit rate was $0.9911$, so the grid needed only 5851 real model
calls. It finished in $2.41$ hours, with no failed units, no retries and no
fallback iterations. There is a separate cache for each seed, so the
replicates remain independent.

\textbf{Design of the factorial.}
The grid has $2^4$ configurations, three convergence thresholds ($0.30$,
$0.50$, $0.80$), five seeds and 40 scenarios, which gives 9600 units. For each
seed, the main effect of a switch is the mean over the cells where it is
ablated minus the mean over the cells where it is not, averaged over all
combinations of the other three switches. The deviation is then taken across
the five seeds. A two way interaction is half the difference between the
effect of one switch when a second switch is ablated and its effect when the
second switch is not ablated.

Removing the \textsc{unknown} hypothesis lowers abstention by $0.0985$ and

Only one two way interaction can be resolved with five seeds. The $U \times S$
term is $+0.0833 \pm 0.0115$, which is about seven times its deviation and the
same size as the main effect of the sanity gate. It is easy to interpret. Both
mechanisms push confidence towards \textsc{unknown}, so they partly do the same
job, and removing both costs less than the sum of removing each one. The
$U \times A$ and $S \times A$ terms are each one deviation from zero. The three
terms which involve $P$ are exactly zero, as they must be when the effect of
$P$ itself is zero. We claim no interaction other than $U \times S$.

\textbf{\finding{Finding 3 (the effect by regime).}}
Broken out by regime, the main effect of $U$ on abstention is $-0.5500 \pm
0.016$ on sparse evidence and $-0.0063 \pm 0.013$ on unknown attacks. For $S$
the corresponding figures are $-0.4500$ and $-0.0063$. On sparse situations
the all-on configuration abstains at $1.0000$ and the minus-$U$ configuration
abstains at $0.0000$, so on this regime the mechanism decides between always
declining and never declining. On the other three regimes the same switch
moves the rate by between $0.005$ and $0.04$. Figure~\ref{fig:ablation} shows
this directly.

Thus the mechanisms act where the evidence is scarce, and they do very little
where the attack is unfamiliar. We note that the unknown attack regime is the
one where an intrusion triage system would most need them, and that the two
level abstention claim rests on this regime.

\textbf{\finding{Finding 4 (the persistence requirement).}}
The persistence requirement is a single line of code. If the dominant
hypothesis has not yet led for the required number of consecutive iterations,
the line caps the convergence score at the threshold minus $0.01$. By default
the required number is two, i.e., a belief has to lead twice in a row before
the system may act on it. This never happens, and the reason lies in the
structure of the code and not in the statistics.

At every iteration the generation step builds a new hypothesis list. It parses
the new response, creates hypothesis records with new identifiers, and keeps
from before only the \textsc{unknown} entry, whose identifier is fixed. The
named hypotheses of the previous iteration are dropped instead of being
updated. In the all-on cell at the standing threshold there are 963 analyses
with more than one iteration, and 10{,}068 named hypotheses. None of these
hypotheses appears in more than one iteration. The dominant iteration counter
is $0$ in all 4382 terminated records, and \textsc{unknown} recurs in all 963
analyses. Hence a requirement of two consecutive dominant iterations cannot be
met.

The threshold sweep shows the consequence. With persistence enabled the
convergence fraction is $0.0000$ at every threshold. The largest convergence
score reached is the threshold minus $0.01$, that is $0.2900$ at threshold
$0.30$ and $0.4900$ at threshold $0.50$, and this is simply the value set by
the clamp. With persistence ablated the convergence fraction at threshold
$0.30$ is $0.5561$. So lowering the threshold does not, on its own, bring the
dead metrics back.

The other mechanism which could hold convergence down is belief inertia. To
separate the two, we crossed persistence and inertia at threshold $0.30$, with
all other mechanisms enabled. Removing persistence raises the convergence
fraction by $+0.3057$. Removing inertia changes it by $+0.0000$, and the
maximum convergence stays at $0.2900$. Inertia does have an effect, but only
after persistence has been removed, and the effect is on how the loop
converges. With persistence off, lifting the inertia cap raises the rate of
conclusions after one iteration from $0.0897$ to $0.1437$, and it lowers the
mean number of iterations from $2.6640$ to $2.6000$. So inertia works as it was
designed to, but while persistence is in place its effect cannot be seen.

plot the belief trajectories of the named hypotheses, but it turns out that
there are no such trajectories to plot.

\textbf{\finding{Finding 5 (the sensor level of abstention).}}
According to its description the system abstains at two levels, at the sensor
and in the reasoning loop. We tested the sensor level directly, on the unknown
attack regime, with a four cell design which crosses the sensor reject option
with the epistemic controls, at five seeds. To disable the sensor level we
clear the abstention flag on every signal before it is ingested. This is the
strongest intervention available to us.

The two sensor rows are the same. Clearing every abstention flag changes the
outcome by $+0.000000$ with the epistemic controls on, and by $+0.000000$ with
them off. So the two levels do not complement each other, and they are not
redundant either, since the second level never receives anything from the
first. The flag is counted into the reasoning snapshot, as an abstained
evidence count and an abstained fraction, and after that nothing reads it. It
does not filter evidence. It is not used in the mean anomaly score, the source
diversity or the confidence level. It is also not one of the ten fields passed
through the information barrier, so the model never sees it. In the suite the
abstained fraction is $0.2285$ overall and $0.5467$ on the unknown attack
regime, and none of it has any effect.

We conclude that the two level abstention design is not implemented. This
conclusion rests on the experiment and not only on reading the source. The
four cell design was run as planned, and the sensor axis has no effect because
there is no path along which it could act.

\section{Order of the Evidence}
\label{sec:confirmation}

In this section we say in which order the evidence was collected. We think
this matters, since a diagnosis made before an experiment is a prediction,
while a diagnosis made after it is only an explanation.

The persistence clamp was found during a mock rehearsal of the grid, before
any real model calls had been made for the factorial. The commit for the
rehearsal records that every configuration with persistence enabled stayed at
a convergence score of $0.2900$, i.e., the threshold minus $0.01$, and it names
the clamp as the cause. The factorial, with 9600 units against the real model,
then confirmed this, and the isolation experiment of
Section~\ref{sec:findings} confirmed it again against the only other
explanation we could find.

Suppose instead that the grid had been run first. We would then have had a
table in which $A$ and $P$ have null effects, and the obvious reading of such a
table is that both mechanisms are unimportant. For $P$ the correct reading is
that it is not connected to anything it could affect, and for the sensor
reject option it is that there is no path at all. These are two different
defects, which need different fixes, and an ablation cannot separate them. We
therefore suggest a simple rule. Before a mechanism is ablated, one should
check, by inspection or by instrumentation, that there is a path from the
mechanism to the metric, and this check should be reported together with the
ablation.

\section{The Repair Experiment}
\label{sec:repair}

The diagnosis above combines code reading with a null effect, and so it is
correlational. A more direct test is to supply the missing precondition and to
see whether the mechanism then works. We describe this test now.

\textbf{Design.}
The design was fixed before the experiment was run. A newly generated
hypothesis takes over the identifier and the dominant iteration counter of the
earlier hypothesis which it restates. Nothing else is carried over, and the
description and the confidence are those produced by the model. The prompt
contains only descriptions and confidences. Hence every prompt issued in a
repaired run is byte for byte equal to a prompt already issued in the
unrepaired run, and early termination can only make an analysis shorter. In
this sense the repair leaves the prompts unchanged. The budget gate confirmed
this: in 42{,}863 cache lookups the repaired grid had no cache misses, so it
cost nothing to run.

\textbf{The matching rule.}
To match two hypotheses we normalise both of them to lowercase alphanumeric
words and compare them with a sequence matcher. A pair is accepted if the
similarity is at least $0.70$, and pairs are assigned greedily and one to one,
in decreasing order of similarity. The threshold was calibrated on the
baseline logs before the repair was run. Note that this is matching
\emph{within} one analysis, between consecutive iterations of the same loop.
This is much easier than matching free text against a ground truth catalogue,
since the two texts are written a few seconds apart by the same model about
the same situation. The calibration agrees with this. In the baseline logs
there are 917 pairs of consecutive iterations whose texts are byte identical,
and each of them still received a new identifier.

We sampled thirty matched chains and read them by hand, with a pass mark of 24
set in advance. In all thirty the matched hypotheses are restatements of the
same hypothesis. One of them is borderline (the subject stays the same but the
wording about severity changes), and if we count it as a failure we still have
29 out of 30.

we use the all-on cell of the factorial at the same threshold and seed, so the
baseline was not run a second time.

With the repair, the identities of hypotheses are kept. Recurrence goes up from
$0$ to $0.2045$, and the dominant iteration counter reaches three, whereas
before it never went above one. At threshold $0.30$ the distribution of the
counter changes from $\{0{:}300,\,1{:}663\}$ in the baseline to
$\{0{:}300,\,1{:}328,\,2{:}250,\,3{:}85\}$ with the repair. Thus 335 analyses
now meet a requirement which no analysis met before.

Persistence now gates convergence. At threshold $0.30$ the convergence
fraction goes up from $0.0000$ to $0.1551$, the mean number of iterations falls
below three for the first time, and the largest convergence score goes up from
$0.2900$ (the value of the clamp) to $0.4530$ (a value produced by the dynamics
of the loop). We conclude that the mechanism was specified correctly, and that
the defect lies in the way it was coupled to the generation step.

\textbf{Limits of the repair.}
At thresholds $0.50$ and $0.80$ the convergence fraction stays at zero, and
here the clamp is not the reason. Under the repair the largest convergence
score is $0.4620$ at both thresholds, which is below each of them, so some
other bound applies. From the source code we can see two causes which
contribute to it. First, the convergence score is not the confidence of the
dominant hypothesis. It is a spread statistic of the form
$\min(2\sigma + \mu/2,\, 1)$, where $\sigma$ is the gap between the largest
and the mean confidence and $\mu$ is the margin over \textsc{unknown}, and it
is further multiplied by penalties when the distribution is flat. Second, the
confidence of a new hypothesis is restricted to the interval $[0.1, 0.5]$ when
it is created. Both of these keep the score well below the standing threshold.
We report this as a second structural ceiling. It is based on code inspection
and it agrees with the measurements, but we did not run the experiment which
would separate the two causes.

The second limit is that recurrence reaches $0.2045$ and not $1.0$. At each
iteration about four named hypotheses in five are still new, so the repair can
help only the remaining one. We have not established whether this is a limit
of the matching rule or of the way the model generates hypotheses.

\section{An Evaluation Hazard}
\label{sec:hazards}

In this section we describe a second result of the audit, which concerns the
way a timing defect interacts with an abstention metric.

The system reasons over archived events, and a staleness check decides
whether a situation is quiet. Suppose the check measures the age of the
evidence in host time, while the events carry archival timestamps. Then the
two clocks are mixed up and every situation looks old. We made this defect a
parameter of the system and ran three clock modes, each at five seeds.

With the clocks conflated, the quiet fraction is $1.0000$ in all five seeds,
i.e., every situation is marked quiet. Trend detection fails as well. The
conflated mode emits only two of the three trend labels, and the stable label
does not appear once in 14{,}445 iterations.

The effect on the headline metric is shown in Figure~\ref{fig:clock}. With the
clocks conflated, the rate of correct conclusions goes up from $0.22$ to
$0.50$. Looking only at this number, one would conclude that the defective
configuration is the better one.

The increase comes from abstention. Since every situation is marked quiet, the
abstention rate goes up from $0.1818$ to $0.5273$, and since three of the four
regimes count an abstention as correct, the score improves. On the one regime
where the system has to commit, the defect makes it worse, and the rate on the
clear regime falls from $0.130$ to $0.080$. We expect the same thing to happen
in other systems. Any replay based evaluation which counts abstention as
correct in most regimes, and which measures staleness in wall clock time
instead of event time, will reward this defect. So the hazard comes from the
scoring rule, and not from this particular corpus. We also note that the
effect seems to have a threshold. A quiet fraction of $0.21$ changes nothing,
while a quiet fraction of $1.00$ changes the outcome completely.

\section{Threats to Validity}
\label{sec:threats}

\textbf{Scale.} The evaluation is synthetic. There is no deployment and no
study with operators. The sub-suite has 40 scenarios and 66 situations, so
each regime has about 16 situations, which gives a binomial interval of
roughly $\pm 0.245$ at 95\,\%. Five seeds are enough for the main effects and
for the one interaction we claim, but we do not report significance tests.

\textbf{Narrative identity.} The ten fields passed through the information
barrier separate the four evidence regimes, with a lift of $0.288$ over the
base rate. They carry no information about the narrative of a scenario (the
lift is $-0.105$). Two of the six narrative categories have the same detector
signature, so they cannot be told apart at all. Hence a metric which checks
whether the system named the right attack really measures overlap of
vocabulary, and for this reason we leave the conclusion metrics out of every
claim in the paper. They are reported, with this caveat, in the supporting
material.

\textbf{The sensor.} We treat the sensor as a part of the instrument, and we
characterise it only as far as the audit needs. The multi source condition in
the suite is constructed and not observed. We did not sweep the confidence
weighting coefficients inside the evaluation step, so it is possible that part
of the inertia of the system comes from their values.

\textbf{Non-determinism.} The language model is not deterministic. The caches
are kept separately for each seed, so the replicates stay independent. The
grid recorded no fallback iterations, so none of the results depends on a
degraded path.

\textbf{Generality.} All findings come from one system. In particular, the
conflation hazard is shown on a single corpus which happens to be stale
throughout, and the threshold behaviour is based on two observations, not on a
curve. What we expect to carry over to other systems is the method, together
with the ambiguity of null ablation results which it resolves. The particular
verdicts may well be different elsewhere.

\section{Reproducibility}

A single script in the project root regenerates all figures of the paper and
recomputes all quoted numbers from committed machine readable results, with no
API key and no network connection. On a clean checkout it reports five stages
passed, none failed, and all eighteen quoted numbers reproduced to within
$5 \times 10^{-4}$. When we first ran it on a clean checkout it found two real
defects in our own artefacts, and both have since been fixed.

Over the whole project, $91.2$\,\% of the 130{,}436 model calls were answered
from the content addressed cache, so they were not paid for twice. The repair
experiment of Section~\ref{sec:repair} was answered entirely from the cache and
cost nothing, as one would expect for a repair which does not change the
prompts.

\section{Conclusion}

We audited four hand designed epistemic controls in a working intrusion
triage agent. One of them works, one works but largely repeats the first, one
is inert at the resolution of five seeds, and the one described as a
persistence requirement is in fact a clamp. A fifth mechanism, the reject
option of the sensor, is specified but not enacted, and clearing it on every
signal of the suite changes the outcome by $0.000000$. A repair which leaves
the prompts unchanged confirms the persistence diagnosis. It raises recurrence
from zero to $0.2045$, and the mechanism then gates convergence for the first
time.

The main lesson is about the order in which things are checked. A null effect
in an ablation may mean that a mechanism does little, or that it is not
connected, and these two cases need quite different responses. We therefore
suggest that one should first establish that there is a path from the
mechanism to the metric, and only then measure the size of the effect along
it. In the system examined here, two of the five mechanisms fail this check,
and a third has no effect that we can measure.
